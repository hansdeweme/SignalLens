# Provenance workspace

ProvenanceWorkspace replaces the transitional destination with a summary and two tabs: Recorded metadata and Contextual research / OSINT. Identity, analysis revision and recorded source hash remain visible above the tabs. Declaration and recorded verification flags use the existing UI-1 projection. The extraction status is separate from those flags and from detector finding strength.

MetadataField and ProvenancePresentation are frozen contracts. The adapter copies raw_key/group/value exactly, preserving newlines and structured technical values. Watchlist and signal entries with the same field/value are combined while retaining their recorded origins and interpretations. IDs hash the original tag/value representation. Source-file properties are explicitly labeled identity, not origin verification. Binary values become length/hash descriptors without exposing their bytes.

The native table supports namespace and name/value search; filtered-out rows do not remain selected. Values are bounded to 180 characters in the table and 64,000 in selected text, with an explicit limit notice. The original recorded payload retains longer values. Detail exposes technical tag, source, trust, recorded interpretation, exact evidence association and limitations. Full limitations are copyable in detail and available from the footer tooltip. Splitter proportions persist in workspace preferences.

Live runs use the already extracted exif_payload. Stored runs may recover only the known <stem>_exif_signals.json contract within the original run root, after matching manifest result/source identity and the payload source SHA-256. Recovery uses the existing bounded worker pool and checks the active session/result/revision on delivery. No arbitrary crawl, ExifTool rerun or new extraction engine is introduced. Payloads over 16 MiB fall back to summary evidence. Metadata structure is cached by forensic identity and is not rebuilt for annotation-only edits.

Unverified declarations, ambiguous/missing provenance and unavailable extraction retain their recorded states. C2PA presence never establishes verification. The UI explicitly states cryptographic verification is unsupported; an imported verification flag remains a historical recorded flag rather than an independent authentication result. The extractor persists selected watchlist/signal evidence rather than the complete original EXIF record, so a short table does not prove that the source file had no other metadata.
