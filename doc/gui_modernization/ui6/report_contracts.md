# Report contracts and supported outputs

UI-1 ReportSnapshot remains the authoritative frozen `(session_id, result_id, annotation_revision, payload_json)` export contract. Its payload already includes analysis ID/revision, source path/hash, profile/configuration or historical import identity, frozen summary fields, reasoning trace, analysis-time annotations, current annotations and their separate appendix. Imported results use fresh local identities and retain historical metadata explicitly.

UI-6 ReportPresentation wraps that same snapshot, exposes analysis ID/revision and supplies HTML, TXT and JSON preview representations. It calls the existing generator-footer helpers used by persist_summary_result. It does not construct a competing narrative or select new conclusions. HTML preview uses the existing theme adaptation; Qt layout may differ from a browser, while its source content derives from the same payload. External resource loading is disabled in preview.

Supported exports remain summary HTML, TXT and JSON, reasoning JSON/text (including the existing recorded-field fallback), current annotation JSON and a current_report.json pointer. The format selector selects the preview representation; Export current snapshot writes the existing complete bundle. No PDF, new template framework, additional provenance verification or new image embedding is introduced. Existing artifact references remain recorded references.

Preview construction is cached by forensic identity and annotation revision, not repeated on navigation. A source-less/narrative-only stored result can still preview and export its exact existing text through forensic_html's escaped fallback. Source/profile values are visible in the report header tooltip and structured JSON where recorded; absent values remain explicit.

Before export, snapshot_is_current verifies the active owner/result/annotation revision. The captured immutable snapshot is sent to a dedicated single-thread report pool; file generation never reads live widgets or mutable annotation objects. The existing publisher runs against a detached owner in a new request directory `<chosen folder>/<session>/<result>-a<revision>-<request>/`. Its immutable generation and atomic pointer remain unchanged. This isolates it from both the live-run pointer and other export requests.

A late request may finish its explicitly captured historical bundle, but cannot overwrite a newer live report pointer or claim current success after the investigation/annotation revision changes. Completion status is accepted only for a known pending request whose snapshot is still current. Failure clears explicit-export success paths and reports the error. Existing automatic run-bundle synchronization and Open Results Folder retain their UI-1 behavior; very large automatic legacy publication is still synchronous and should be profiled in UI-7.
