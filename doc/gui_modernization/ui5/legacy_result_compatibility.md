# Legacy and partial investigations

No stored report is rewritten to populate UI-5 fields. UI-1 remains responsible for import identity, historical metadata, frozen findings and report revisions. Explorers consume only available structures under reasoning_trace and sections.

Missing role arrays do not imply contradiction. Missing detail labels fall back to stable IDs; observations, detector, reliability, availability and lineage remain explicitly unknown. An observed strong/medium/weak status is not promoted into a reliability classification. A policy result can be inspected without a full hypothesis record. Missing route/gate records are shown as unavailable rather than reconstructed from narrative.

An older base_evidence ledger is still inspectable without numerical-allocation fields. Exact totals remain visible if replay is unsupported/incomplete. Arithmetic mismatch is an audit warning and never overwrites scores. Optional shadow lineage is used only if actually persisted; otherwise numerical ancestry and static registry edges are labeled separately. A narrative-only investigation retains Overview/raw narrative access and clear empty explorer states.

The adapters tolerate non-dictionary containers and invalid numeric values without silently substituting zero. Explicit issues identify unsupported/malformed containers where recognized; absent fields stay unavailable. The GUI cannot always distinguish a schema it has never supported from corruption in that schema, and does not claim to repair either. Artifact disappearance affects navigation/preview availability, not historical evidence roles or confidence. The existing partial-result, OSINT and report workflows remain covered by the baseline suite.
