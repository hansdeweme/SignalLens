## Proven geometry and restrictions

* ELA: `ela.ela_image_path`, two hotspot overlays and optional recompressed JPEG in ela_payload; persisted `<stem>_ela.json`. PIL loads encoded source RGB without transpose; diff/recompression/full-canvas drawing preserves source grid. For identity-verified runs and orientation 1, full-grid dimensions must match source. Plain ELA supports registered synchronization and brightness-scaled RGB-difference blend; JPEG/annotated variants support synchronization, not new overlays.
* Noise: residual plus two full-image hotspot overlays in noise_payload, `<stem>_noise.json`. Luminance and Gaussian-blur difference preserve the original encoded grid. Same identity/orientation/dimension conditions as ELA. Plain residual supports registered synchronization and brightness-scaled residual blend.
* Person mask: mask/overlay on prepared `subject` PNG; recorded image_geometry or region_masks shape plus image_gatekeeper's full-frame resize provides an edge-coordinate scale to source. Only reliable/limited person masks can be eligible; rejected/approximate/unavailable masks are unusable for registered comparison. Derived subject/boundary/background masks have the same grid. Nearest-neighbor masks; prepared RGB used LANCZOS. No mask overlay enabled until compositing semantics are explicitly selected.
* Global FFT: spectrum, radial profile and peak map are frequency-domain C diagnostics, never source overlays. Grid response/annotated images use additional production scaling; conservatively UNKNOWN in this phase. Regional FFT subject/boundary/background temporary inputs are soft-mask crops with different padding; crop origins are NOT persisted. Never infer registration from their size. Repeated regional calls overwrite fft_results.json; it can describe the last regional run rather than global FFT. Stored global recovery must not silently use that file as the global detector.
* Patch similarity: prepared patch input then additional max-dimension scaling; overlay is spatial but heatmap is patch-grid data. Scale_info exists in raw/persisted patch payload, yet crop/canvas semantics remain conservatively UNKNOWN here. Patch spatial references the same paths: deduplicate physical artifact entries and retain only explicit recorded section associations.
* CFA, compression, sensor and intrinsic boundary overlays are block/edge annotations. Some consume original images using OpenCV orientation behavior; conservative UNKNOWN avoids assuming PIL/raw orientation equivalence. Subject texture/material/asymmetry overlays depend on masks and sampling geometry; independent inspection only until those transforms are verified.
* Region segmentation, segmentation alignment and cross-signal scalar summaries are D structured evidence where no explicit raster is recorded. Shared-boundary overlays are explicit summary.overlay_paths and remain UNKNOWN until their own compound transformations are validated.

## Discovery constraints and taxonomy

A = verified source-aligned raster; B = demonstrably transformable full-frame raster; C = non-spatial diagnostic; D = structured output without a raster; E = unavailable/corrupt/rejected/untrusted output. Unknown spatial rasters remain independently viewable with UNKNOWN registration, never silently promoted to A/B.

The existing run manifest is not a complete image manifest. Live payloads provide stronger provenance than guessed names. Stored recovery uses an identity-matching run manifest plus a narrow list of known persisted JSON contracts and explicit summary paths. No filesystem image glob/crawl or cross-run basename search is permitted. Legacy identity gaps remain explicit and disable registration. Per-artifact dimensions, content hashes and availability are recorded in UI-4's generated catalog during validation; dimension equality alone never proves registration.
